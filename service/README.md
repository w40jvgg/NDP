# NormalDance Service — демонстрационный интерфейс

Самостоятельный статический прототип сервиса NormalDance Protocol. Он отделён от лендинга и не требует сборщика или внешних зависимостей.

## Что реализовано

- регистрация и вход;
- готовый демо-профиль;
- личный кабинет и редактирование профиля;
- главная панель с метриками и активностью;
- имитация проверки аудиофайла, ADNA и поиска по ISRC / NDP-ID;
- реестр произведений и цифровые паспорта прав;
- пошаговая регистрация произведения с участниками и сплитами;
- политика использования ИИ;
- демонстрационный модуль роялти;
- интерактивный раздел «Как работает»: ADNA → реестр прав → каскадное распределение выплаты;
- личные сообщения с сохранением диалогов в браузере и имитацией входящих сообщений;
- 3 демонстрационных диалога о покупке, продаже и обмене сэмплов;
- библиотека сэмплов в личном кабинете с фильтрацией, демо-прослушиванием и условиями лицензий;
- раздел API / MCP;
- светлая и тёмная темы;
- адаптивный интерфейс.

## Важно

Это демонстрация продукта. Реальный ADNA fingerprint engine, реестр PostgreSQL, авторизация на сервере, платёжная инфраструктура и реальные API не подключены.

Все пользовательские данные хранятся только в `localStorage` браузера. При проверке аудио файл не отправляется на сервер: браузер вычисляет SHA-256 и использует его только как детерминированный seed для имитации результата.

## Запуск

Можно открыть `index.html` напрямую. Для более реалистичной проверки рекомендуется любой статический сервер, например:

```bash
python -m http.server 8080
```

После этого открыть `http://localhost:8080`.

## Профили участников переписки

Три демонстрационных собеседника — KERA, Sample Lab и MIRA — имеют отдельные публичные NDP-профили. В профиль можно перейти нажатием на имя/аватар или кнопку «Профиль» в заголовке диалога. Для каждого профиля заданы аватар, NDP-ID, статус верификации, специализация, жанры, условия работы, статистика, рейтинг и публичная библиотека объектов. Из профиля можно вернуться в исходный диалог или сразу продолжить переписку.

## Проверка интерфейса

После добавления профилей повторно проверены основные и вспомогательные сценарии интерфейса: авторизация и регистрация, навигация, верхняя панель, сообщения, переходы в профили и обратно, отправка/имитация входящих сообщений, библиотека сэмплов, демо-прослушивание, проверка ADNA/ID/аудиофайла, реестр, мастер регистрации, демонстрация «Как работает», API/MCP, настройки, темы, сброс данных, выход и мобильное меню. Уведомления переведены в режим `pointer-events: none`, чтобы всплывающие сообщения не перекрывали элементы управления.
